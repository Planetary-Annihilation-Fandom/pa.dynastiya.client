# Версионирование

При работе над UI начинай с аудита и очевидных общих исправлений; достаточно одного характерного примера изменённого механизма. Числовые метрики, профилирование и полный обход экранов не обязательны; декоративные пульсации, тени и свечения убирай по решению пользователя без требования доказать ускорение каждого удаления.

Автотесты и постоянные скрипты проверок в проекте не пишутся: они закрепляли детали реализации и мешали исправлять видимое поведение. Проверяй изменения в игре по скриншотам; разовые скрипты держи в `mods/dynastiya/scratchpad/<задача>/`, этот каталог не попадает в git.

Строки интерфейса пиши через `loc('!LOC:English text')`.

Общие правила UI находятся в [`docs/ui/README.md`](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.server/blob/main/docs/ui/README.md) серверного репозитория. Результат и проверку описывай в сообщении коммита и в комментарии при закрытии issue.

Все задачи «Династии», включая клиентские, веди в [Issues серверного репозитория](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.server/issues).

Каждую задачу выполняй в отдельной ветке от `dev`. Создавай коммиты, отправляй изменения в `origin` и открывай pull request только с явного разрешения пользователя на соответствующие действия.

В `dev` и `main` вливай только через pull request с merge-коммитом. При открытии PR запроси в GitHub ревью у всех коллабораторов-людей с правом записи, кроме автора PR. Слияние требует одобрения каждого из этих ревьюеров и явного разрешения пользователя. Любое другое слияние веток, включая fast-forward, также требует явного разрешения пользователя.

Зависимости из строки «Нужно до начала работ» должны быть влиты в `dev` соответствующего репозитория. Для разрешённого пользователем выпуска открой PR из `dev` в `main` с обновлёнными `version` и `date` в `modinfo.json` изменённой части. После слияния поставь тег и синхронизируй `dev` отдельным PR из `main`. Порядок работы описан в [руководстве](https://github.com/Planetary-Annihilation-Fandom/pa.dynastiya.server/blob/main/docs/publishing.md).

Версии клиентской и серверной частей ведутся независимо в их `modinfo.json` по схеме `x.y.z`: `x` повышается при существенном нарушении совместимости, `y` — при необходимости миграции сохранённых данных, `z` — при остальных изменениях. Подготовь новую версию и дату выпуска в отдельной ветке от `dev` и внеси их в `dev` до слияния релизного PR. Прямое указание пользователя повысить версию сейчас имеет приоритет.
